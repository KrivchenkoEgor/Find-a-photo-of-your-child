# 🔍 Поиск фото ребёнка

Приложение для macOS, которое находит в семейном архиве **снимки конкретного человека**.
Вы один раз показываете ему, где ваш ребёнок на нескольких своих фото, — и он перебирает
тысячи снимков и отвечает: «вот эти, с такой степенью похожести».

Ни один файл не покидает ваш компьютер. Облака, аккаунта и интернета для работы не нужно.

| | |
|---|---|
| Платформа | macOS 26 и новее, только Apple Silicon (M1–M4) |
| Готовый носитель | скачать в релизе: [`FindChild.dmg`, 302 МБ](https://github.com/KrivchenkoEgor/Find-a-photo-of-your-child/releases/latest/download/FindChild.dmg) |
| Скорость | 131 фото, «внимательный» разбор, с нуля — 255 с; повторный — секунды |
| Тесты | 635 быстрых + 6 боевых на реальном архиве |
| Лицензия | MIT |

## Зачем, если есть фото-приложения телефона

Галерея телефона и «Поиск по лицам» в облаке решают другую задачу: они сами группируют
все лица в вашем архиве. Здесь задача одна — **найти снимки одного-двух конкретных
людей**, и решается она на ваших условиях:

- архив может лежать на внешнем диске, в папке, которую вы покажете сами;
- никто не решает за вас, кто на фото «тот же человек», — вы отмечаете лица руками;
- снимки не уходят в облако и не проходят через чужие серверы;
- работает со снимками iPhone (`.heic`), с поворотом по EXIF, из нескольких папок сразу.

## Как это работает

```
папка с фото → детектор находит лица → каждое лицо = 512 чисел (отпечаток)
                                            ↓
                  вы отмечаете, какие лица — ваш ребёнок
                                            ↓
        каждый отпечаток архива сравнивается с отмеченными → процент похожести
                                            ↓
              сетка карточек → ваша галочка → копирование + отчёт
```

Три вещи стоит знать про модель, потому что из них растут все числа на экране:

1. **Два детектора, а не один.** YuNet (230 КБ, лежит в репозитории) и SCRFD из пакета
   `buffalo_l` (17 МБ). Режим «Оба» ищет обоими и берёт лучший ответ: один детектор
   регулярно пропускает ребёнка на групповом фото.
2. **Отпечаток лица — это 512 чисел**, а не картинка. Их строит распознаватель
   `arcface_w600k_r50` (174 МБ). Сходство двух отпечатков — косинус угла между ними,
   который приложение показывает в процентах.
3. **Оглавление** — SQLite-база в служебной папке пользователя. В ней лежат отпечатки
   уже разобранных снимков, поэтому второй прогон по той же папке не читает фото заново.

## Что означают числа

Это самый частый вопрос, и он правильный: **процент — не уверенность приложения, а
расстояние между лицами.**

| что вы видите | что это значит |
|---|---|
| `Похоже: 19` | 19 снимков прошли порог. У каждого под миниатюрой стоит зелёная рамка на найденном лице |
| `Слабое сходство: 112` | столько фото не дошло до порога. Кнопка рядом с счётчиком открывает их — там обычно тоже есть нужные снимки |
| `61 %` | совпадение с самым похожим отмеченным лицом. На снимках **одного и того же** ребёнка значение держится в полосе **39–67 %** (замер на архиве из 131 фото) |
| `выше 67 % не бывает` | это не ограничение кода, а свойство распознавателя: разные снимки одного человека никогда не дают 100 %. 100 % бывает только на том самом фото, с которого взято отмеченное лицо |
| `Отмечено к копированию: 19` | сколько галочек стоит сейчас. Копируются только они |

Отсюда правило, на котором держится весь интерфейс: **решает человек по зелёной рамке, а
не число.** Порог (ползунок, 30–60 %, умолчалка 38 %) делит список на две кучки и
пересчитывается на лету, без нового разбора папки.

Лиц на одного человека можно отметить сколько угодно — чем больше, тем увереннее поиск.
Людей может быть несколько («Добавить ещё одного»), и каждый ищется отдельно: на карточке
будет написано, кто именно найден на снимке, например `ребёнок 61 % · мама 44 %`.

## Установка

### Готовое приложение (macOS)

Нужно: macOS 26+, Apple Silicon, ~600 МБ свободного места.

**Файл лежит в релизах** — скачивается без установки и без входа в аккаунт:

- образ: <https://github.com/KrivchenkoEgor/Find-a-photo-of-your-child/releases/latest/download/FindChild.dmg> (302 МБ)
- страница релиза с инструкцией первого запуска: <https://github.com/KrivchenkoEgor/Find-a-photo-of-your-child/releases/tag/v1.0>

Тот же образ можно собрать из исходников на своём Маке:

```bash
git clone https://github.com/KrivchenkoEgor/Find-a-photo-of-your-child.git
cd Find-a-photo-of-your-child
./make_dmg.sh                       # → dist/FindChild.dmg
```

Дальше: открыть `FindChild.dmg`, перетащить «Поиск фото» в папку «Программы».

**Первый запуск macOS заблокирует**: подпись у приложения служебная (ad-hoc), платного
сертификата разработчика нет. Снимается одним действием:

- правый клик по приложению → **«Открыть»** → «Открыть всё равно», после чего обычный
  двойной клик работает всегда; или
- `xattr -dr com.apple.quarantine "/Applications/FindChild.app"` в Терминале.

Блокировка касается только скачанного из интернета: с флешки или с собственного диска
приложение стартует без предупреждения.

### Из исходников

```bash
uv venv --python /opt/homebrew/opt/python@3.11/bin/python3.11 .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python src/main.py
```

`insightface` ставится из того же `requirements.txt` отдельно и без зависимостей
(`--no-deps`): он тянет `opencv-python`, который затирает собой
`opencv-python-headless` — оба укладывают свой код в один каталог `cv2`. Подробности —
в комментариях в начале `requirements.txt`.

**Модели.** YuNet (230 КБ) лежит в репозитории. Пакет распознавания `buffalo_l`
(~290 МБ) при первом разборе скачивается сам в `~/.insightface/models/buffalo_l` — один
раз, нужен интернет. В собранном `.app` нужные два файла (191 МБ) уже лежат внутри
архива, и там он не качается никогда.

## Как пользоваться

Одно окно, три шага сверху вниз.

1. **«Где ищем»** → «Добавить папку с фото». Папок может быть несколько; вложенные друг
   в друга не считаются дважды. Строка справа скажет, сколько снимков найдено.
2. **«Кого ищем»** → «Выбрать фото: ребёнок». Откроется окно с карточками: на каждом
   снимке все найденные лица подписаны номерами, и вы галочками отмечаете те, где
   ваш человек. Кнопка «Искать по этим лицам» завершает выбор.
   Карточка помечена **зелёной рамкой**, если поиск идёт по этому лицу, и **красной**,
   если вы его сняли.
3. **«Начать разбор папки»**. Тяжёлая работа идёт в отдельном потоке: окно не висит,
   полоса показывает прогресс, «Остановить» добирает уже сделанное.
4. **«Что показало»**: ползунок похожести, «поиск» (Оба / Быстрее / Точнее) и «качество
   разбора» (внимательное 2400 px / обычное 1200 px). Первые два применяются сразу,
   смена качества требует нового разбора. «Забыть разобранные фото» чистит оглавление.
5. **Двойной клик по карточке** открывает снимок целиком: там то же лицо крупно (320 px),
   рамка на каждом найденном лице, стрелки «← предыдущее фото» и «следующее фото →»
   и галочка «копировать это фото» — та же самая отметка, что под карточкой.
6. **«Скопировать отмеченные»** → вы выбираете папку, в неё ложатся снимки и два отчёта.

## Отчёты

Рядом со скопированными фото появляются `report.txt` и `results.csv`. Первый читается
глазами, второй открывается в Excel.

```
Итог
  фото в отчёте: 131
  фото с лицами: 118
  похоже: 19
  слабое сходство: 99
  скопировано: 19

Найденные фото — по убыванию похожести, при равных числах по имени файла
   61%  DSC_0417.jpg           лиц: 3   похоже
   58%  IMG_8842.heic          лиц: 2   похоже

Потери — чтобы «похожих: 0» не читалось как «ребёнка в архиве нет»
  файлов не обработано: 1
  снимок не читается — файлов: 1
    примеры: DSC_9999.jpg
```

Колонки `results.csv`: `файл, процент, лиц, похоже, рамка` — координаты совпавшего лица,
чтобы можно было проверить кадр программно. Если людей в поиске больше одного, добавляются
колонки «кто найден и насколько похож» и «на какое лицо похоже».

Порядок строк в сетке, в `report.txt` и в CSV задаётся одним общим правилом
(`core/report.py`), поэтому три вида отчёта не расходятся.

## Скорость и качество разбора

Замерено на архиве 131 фото (24 Мп, JPEG), Apple Silicon, режим «Оба»:

| прогон | время |
|---|---|
| первый, «внимательное» (2400 px) | 255 с |
| повторный, всё взято из оглавления | единицы секунд |
| перетасовка порога ползунком | меньше секунды, модели не работают |

Размер собранного приложения: `FindChild.app` — 554 МБ, из них 191 МБ веса распознавания
и ~120 МБ Qt. Носитель `FindChild.dmg` — 302 МБ.

## Конфиденциальность

Что приложение делает с данными:

- **читает** указанные вами папки с фото, ничего в них не записывая и не меняя;
- **пишет** в служебную папку пользователя: `settings.ini` (настройки) и `cache.sqlite3`
  (оглавление);
- **не отправляет** ничего. Интернет нужен ровно один раз — скачать веса `buffalo_l`,
  и то не в собранном `.app`, где они внутри архива.

О оглавлении стоит сказать отдельно: в нём лежат **отпечатки лиц** — 512 чисел на лицо,
из которых нельзя восстановить снимок, но это по-прежнему биометрические данные вашего
ребёнка. Файл лежит здесь:

```
~/Library/Application Support/FindChild/        macOS
%APPDATA%\FindChild\                            Windows
```

Удаление папки возвращает приложение к пустому состоянию (настройки и оглавление), сами
фото не трогаются. Кнопка «Забыть разобранные фото» делает то же самое с оглавлением из
интерфейса.

**Чего нет и не будет в этом репозитории:**

| не публикуется | почему |
|---|---|
| `data/`, `ref/` | снимки ребёнка. Закрыты в `.gitignore` |
| `arhiv.local.json` | путь к семейному архиву и имена конкретных снимков: по одним только именам вместе с логином на GitHub можно восстановить, чьи фото разбирают. В репозитории есть только `arhiv.example.json` с заглушками |
| оглавление, `logs/`, `output/`, `build/`, `dist/` | результаты работы и черновики сборки |
| `Findchild.py` | исходный скрипт-эталон, из которого вырос интерфейс: в нём прописаны личные абсолютные пути автора |
| `progress.md`, `checkpoint.md`, дневники замеров | рабочие журналы: цитируют имена снимков. Выводы из них перенесены в `LESSONS.md` и спецификацию, а в самих этих документах имена заменены на `снимок-NN` |
| `bench_*.py`, `analyze_threshold.py` | калибровочные зонды одноразовой работы с зашитым путём к архиву |
| `assets/samples/` | там лежала стоковая фотография с водяным знаком агентства — публиковать её нельзя, а код её не читает |

Если сообщаете о проблеме — **не прикладывайте скриншоты с лицами**. Нужны номера
карточек, проценты и текст сообщения.

## Тесты

```bash
.venv/bin/python -m pytest -q -m "not slow"     # быстрые: 635 тестов, ~20 с
.venv/bin/python -m pytest -q -m slow -rs       # боевой прогон на реальном архиве, ~5 мин
```

Быстрые тесты (635) поднимают настоящие окна Qt в безэкранным режиме и кликают по ним
мышью: проверяется поведение, а не разметка. Боевые (6) гоняют ядро на вашем архиве и
сверяют находки со списком снимков, которые человек подтвердил глазами, — без
`arhiv.local.json` они пропускаются с внятной причиной, а не «зелёным» результатом.

Пустой `pytest -q` ничего не отфильтровывает: если рядом лежит `arhiv.local.json`, он
заодно прогонит боевой архив через обе модели — 641 тест вместо 635 и 354 с вместо 20.
Быстрые получает только тот, кто передал `-m "not slow"`.

## Структура репозитория

```
src/
  main.py               точка входа
  core/                 логика, не знающая про окно
    scanner.py          поиск файлов, чтение с поворотом по EXIF, HEIC
    yunet.py            детектор YuNet (OpenCV)
    insight.py          SCRFD + arcface через insightface
    both.py             два детектора, слияние лиц в один список
    engine.py           лицо как данные, фабрика движков
    cache.py            оглавление отпечатков (SQLite)
    matcher.py          отпечатки → эталон → процент
    etalon.py           человек: набор отмеченных лиц и его эталон
    worker.py           фоновый разбор, отмена, сбои
    report.py           сетка, report.txt и CSV из одного источника порядка
    copier.py           копирование отмеченных
  ui/
    main_window.py      окно из трёх шагов
    settings.py         полоса настроек, применяемая на лету
    results_view.py     сетка карточек с галочками
    reference_dialog.py окно выбора лиц («Кого ищем»)
    photo_view.py       крупный кадр по двойному клику
    face_picker.py      рамки, кропы, номера лиц — у окна и сетки одни на всех
  utils/config.py       пути, настройки, где лежат модели
tests/                  641 тест; боевые — в test_golden_archive.py
assets/models/          YuNet (230 КБ) — едет внутри приложения
hooks/runtime_hook_cv2.py  чинит загрузчик OpenCV внутри архива
FindChild.spec          что попадает в .app и почему
make_icon.py            рисует иконку (Pillow) и собирает .icns
make_dmg.sh             сборка .app и носителя одной командой
check_env.py            проверка окружения: Python, пакеты, импорт Qt и OpenCV
check_models.py         проверка, что обе модели видят лицо на снимке
AGENTS.md               правила разработки, которым следует этот проект
LESSONS.md              журнал найденных граблей (PySide6, OpenCV, сборка)
```

## Известные ограничения

- **macOS 26+ и только Apple Silicon.** Пол задаёт сборка Python, из которой растёт
  архив, а не код приложения. Для более старых систем нужен другой интерпретатор.
- **Windows не собран.** Код кроссплатформенный, пути идут через `pathlib`, но `.exe` и
  установщик не проверялись ни на одной машине — поэтому в README нет обещаний.
- **Детектор иногда находит не лицо.** Рука на групповом фото может дать 38 % и попасть
  в «похоже». Оценку достоверности YuNet приложение не сохраняет, поэтому отсечь такое
  автоматически нельзя — для этого и нужна зелёная рамка, которую проверяют глазами.
- **Окно выбора эталона замирает** на 15–20 снимках: кропы читаются в потоке интерфейса.
- **Порог не различает возраст и ракурс.** На фото ребенка трёхлетней давности сходство
  ниже, чем на свежих, при том же самом человеке.
- Открытые задачи видны в `LESSONS.md` и по префиксам `T6`–`T9` в коде.
